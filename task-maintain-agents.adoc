= Maintenance des machines virtuelles de l’agent NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Assurer la maintenance des VM d’agent NetApp Console en appliquant les mises à jour de sécurité du système d’exploitation aux agents installés manuellement, en répondant aux alertes relatives au processeur, à la RAM et à l’espace disque, et en redimensionnant, arrêtant et redémarrant les VM en cas de besoin.

Lors de l'installation manuelle d'un agent Console, la maintenance du système d'exploitation sur l'hôte de l'agent relève de votre responsabilité (celle du client). Par exemple, vous (le client) devez appliquer les mises à jour de sécurité au système d'exploitation de l'hôte de l'agent en suivant les procédures standard de votre entreprise en matière de distribution de systèmes d'exploitation.

Si une machine virtuelle d'agent est sous-dimensionnée ou rencontre des problèmes de performance, vous devez prendre les mesures appropriées pour mettre à niveau les ressources de la machine virtuelle.


NOTE: Si vous avez installé l'agent dans vCenter, utilisez l'outil de maintenance de Console pour redimensionner l'instance VM. link:task-agent-vm-config.html["Apprenez à maintenir une machine virtuelle d’agent dans vCenter"^].



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== Appliquez les mises à jour du système d'exploitation aux hôtes d'agent installés manuellement

Appliquez les correctifs de sécurité du système d’exploitation sans arrêter les services hôtes de l’agent.

Pour garantir la compatibilité avec les configurations prises en charge, vous devez empêcher la mise à niveau de Docker ou de Podman lors des mises à jour système de routine. Vous pouvez le faire soit en excluant temporairement Docker ou Podman lors des mises à jour, soit en configurant de manière permanente le gestionnaire de paquets pour ignorer les mises à jour de Docker ou de Podman.

Voici des exemples de procédure pour exclure les mises à jour de Docker ou Podman sur différentes distributions Linux. Consultez la documentation de votre distribution Linux pour obtenir les instructions les plus récentes sur la manière d'exclure des paquets des mises à jour.

.Exemple Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Exemple Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== Redimensionnement de la machine virtuelle ou du type d'instance

Si vous créez un agent de console à partir de la console, il déploie une instance de machine virtuelle dans votre fournisseur de cloud avec une configuration par défaut.  Après avoir créé l'agent, ne passez pas à une instance de machine virtuelle plus petite avec moins de CPU ou de RAM.

Si vous recevez des notifications indiquant que votre machine virtuelle d’agent est sous-dimensionnée, envisagez de passer à une instance de machine virtuelle plus grande avec davantage de CPU ou de RAM afin de garantir des performances optimales.


NOTE: Si vous avez installé l'agent dans VCenter, utilisez l'outil de maintenance de Console pour redimensionner l'instance VM. link:task-agent-vm-config.html["Découvrez comment redimensionner la machine virtuelle de l’agent dans VCenter"^].

link:reference-agent-default-config.html["En savoir plus sur la configuration par défaut de l'agent"] .

Si vous devez augmenter le CPU ou la RAM de votre VM d’agent, suivez les instructions fournies par votre fournisseur de cloud ou votre plateforme de virtualisation sur site pour redimensionner l’instance de VM. NetApp recommande de doubler l’allocation actuelle de CPU et de RAM pour garantir des performances optimales. Le tableau suivant présente les niveaux de dimensionnement recommandés, chaque niveau doublant le CPU et la RAM du niveau précédent.

[cols="1,1,1"]
|===
| Niveau | CPU (cœurs ou vCPUs) | BÉLIER 


| Minimum | 8 | 32 Go 


| Moyen | 16 | 64 GB 


| Grand | 32 | 128 GB 
|===

== Surveiller l'agent

La console vous avertit lorsque la machine virtuelle de l'agent n'est pas saine, notamment en cas de problèmes d'espace disque, de RAM et de processeur.  Surveillez ces notifications dans le centre de notifications de la console ou configurez des notifications par e-mail.  Des augmentations occasionnelles de l'espace disque, de la mémoire ou de l'utilisation du processeur sont normales, mais si cela se produit fréquemment, vous devez prendre des mesures pour résoudre le problème.

Par exemple, la console vous avertit lorsqu'une ressource d'agent (CPU, RAM ou espace disque) dépasse 90 % de sa capacité totale pendant 30 minutes consécutives.  Par la suite, si l’utilisation des ressources descend en dessous de ce seuil, la notification s’affiche comme résolue (verte) dans le Centre de notifications.


NOTE: Travaillez avec le support NetApp si vous avez des questions concernant la modification de votre machine virtuelle d'agent.

== Se connecter à la machine virtuelle Linux

Si vous devez vous connecter à la machine virtuelle Linux sur laquelle l’agent s’exécute, utilisez les options de connectivité de votre fournisseur de cloud.

AWS:: Lorsque vous créez l'instance d'agent dans AWS, fournissez une clé d'accès AWS et une clé secrète.  Vous pouvez utiliser cette paire de clés pour vous connecter en SSH à l'instance.  Utilisez le nom d'utilisateur « ubuntu » pour l'instance Linux EC2.  Pour les agents créés avant mai 2023, utilisez le nom d'utilisateur « ec2-user ».
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentation AWS : connectez-vous à votre instance Linux"^]

--
Azuré:: Lorsque vous créez la machine virtuelle de l’agent dans Azure, vous spécifiez un nom d’utilisateur et choisissez de vous authentifier avec un mot de passe ou une clé publique SSH.  Utilisez la méthode d’authentification que vous avez choisie pour vous connecter à la machine virtuelle.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure Docs : Connectez-vous à votre machine virtuelle via SSH"^]

--
Google Cloud:: Vous ne pouvez pas spécifier de méthode d'authentification lorsque vous créez un agent dans Google Cloud.  Cependant, vous pouvez vous connecter à l'instance de machine virtuelle Linux à l'aide de la console Google Cloud ou de Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs : Se connecter aux machines virtuelles Linux"^]
