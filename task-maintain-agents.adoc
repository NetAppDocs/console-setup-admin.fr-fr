Assurez-vous que vos machines virtuelles d’agent Console sont à jour, correctement dimensionnées et en bon état de fonctionnement afin que l’agent reste opérationnel en permanence.



[[apply-operating-system-updates-to-agent-hosts]]
== Appliquer les mises à jour du système d'exploitation aux hôtes d'agents

Appliquez les mises à jour de sécurité au système d'exploitation et aux paquets associés sur l'hôte de votre agent afin que cet hôte reste sécurisé.

Cela relève de votre responsabilité en tant que client. Le logiciel d'agent Console peut se mettre à jour automatiquement, mais il ne met pas à jour le système d'exploitation ni les packages associés.


NOTE: Si vous avez déployé l’agent Console dans vCenter à l’aide d’un fichier OVA, le système d’exploitation fait partie de l’image de l’agent. link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["Mettez à niveau l'agent à l'aide d'une image ISO"^] pour mettre à jour le système d’exploitation.

Suivez les procédures standard de votre entreprise pour votre distribution du système d'exploitation. Il n'est pas nécessaire d'interrompre les services hôtes des agents lors de l'application des correctifs de sécurité du système d'exploitation.

Sur les agents que vous n’avez pas déployés à partir d’un fichier OVA, empêchez la mise à niveau de Docker ou de Podman lors de l’application des correctifs de routine du système d’exploitation afin de maintenir la compatibilité avec les configurations prises en charge. Vous pouvez le faire soit en excluant temporairement Docker ou Podman lors des mises à jour, soit en configurant de manière permanente le gestionnaire de paquets pour ignorer les mises à jour de Docker ou Podman.

Voici des exemples de procédure pour exclure les mises à jour de Docker ou Podman sur différentes distributions Linux. Consultez la documentation de votre distribution Linux pour obtenir les instructions les plus récentes sur la manière d'exclure des paquets des mises à jour.

.Exemple Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Exemple Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== Redimensionner la machine virtuelle ou le type d'instance

Augmentez le CPU ou la RAM d'une VM d'agent sous-dimensionnée afin que l'agent continue d'offrir de bonnes performances.

Si vous créez un Console agent à partir de la Console, une instance de VM est déployée chez votre fournisseur de cloud avec une configuration par défaut. link:reference-agent-default-config.html["En savoir plus sur les paramètres par défaut de l'agent"]. Après avoir créé l’agent, ne passez pas à une instance de VM plus petite avec moins de CPU ou de RAM.

Si vous recevez des notifications indiquant que votre VM d’agent est sous-dimensionnée, envisagez de passer à une instance de VM plus grande avec plus de CPU ou de RAM.


NOTE: Si vous avez installé l'agent dans vCenter, utilisez l'outil de maintenance de Console pour redimensionner l'instance VM. link:task-agent-vm-config.html["Découvrez comment redimensionner la machine virtuelle de l’agent dans vCenter"^].

Si vous devez augmenter le CPU ou la RAM de votre VM d’agent, suivez les instructions fournies par votre fournisseur de cloud ou votre plateforme de virtualisation sur site pour redimensionner l’instance de VM. NetApp recommande de doubler l’allocation actuelle de CPU et de RAM pour garantir des performances optimales. Le tableau suivant présente les niveaux de dimensionnement recommandés, chaque niveau doublant le CPU et la RAM du niveau précédent.

[cols="1,1,1"]
|===
| Niveau | CPU (cœurs ou vCPUs) | BÉLIER 


| Minimum | 8 | 32 Go 


| Moyen | 16 | 64 GB 


| Grand | 32 | 128 GB 
|===

== Surveiller l'agent

Restez informé des problèmes d'espace disque, de RAM et de processeur sur la VM de votre agent afin de pouvoir les résoudre.

La console vous avertit lorsque la machine virtuelle de l'agent n'est pas saine, notamment en cas de problèmes d'espace disque, de RAM et de processeur.  Surveillez ces notifications dans le centre de notifications de la console ou configurez des notifications par e-mail.  Des augmentations occasionnelles de l'espace disque, de la mémoire ou de l'utilisation du processeur sont normales, mais si cela se produit fréquemment, vous devez prendre des mesures pour résoudre le problème.

Par exemple, la console vous avertit lorsqu'une ressource d'agent (CPU, RAM ou espace disque) dépasse 90 % de sa capacité totale pendant 30 minutes consécutives.  Par la suite, si l’utilisation des ressources descend en dessous de ce seuil, la notification s’affiche comme résolue (verte) dans le Centre de notifications.


NOTE: Travaillez avec le support NetApp si vous avez des questions concernant la modification de votre machine virtuelle d'agent.

link:https://docs.netapp.com/us-en/console-setup-admin/task-monitor-cm-operations.html#notification-center["Apprendre encore plus."^]

L'utilisation du processeur est trop élevée
 a| 
Augmentez la puissance du processeur de la machine virtuelle de l'agent, que ce soit chez votre fournisseur de cloud ou sur site, selon son emplacement d'installation. Vous pouvez également créer des agents supplémentaires et répartir le workload entre eux.

[[stop-and-start-the-agent-vm]]
== Arrêtez et démarrez la machine virtuelle de l'agent

Limitez l'interruption lors de l'arrêt et du redémarrage de la machine virtuelle de l'agent, car les services de gestion et de données dépendent du maintien en fonctionnement de l'agent.

Si nécessaire, arrêtez et démarrez la machine virtuelle de l'agent à l'aide de la console de votre fournisseur de cloud ou des procédures standard sur site.

link:concept-agents.html#agents-must-be-operational-at-all-times["Sachez que l'agent de la console doit être opérationnel à tout moment"] .



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Se connecter à la machine virtuelle Linux

Vérifiez l’état de l’agent Console depuis sa machine virtuelle Linux afin de confirmer qu’il est en cours d’exécution.

Si vous devez vous connecter à la machine virtuelle Linux sur laquelle l’agent s’exécute, utilisez les options de connectivité de votre fournisseur de cloud.

AWS:: Lorsque vous créez l'instance d'agent dans AWS, fournissez une clé d'accès AWS et une clé secrète.  Vous pouvez utiliser cette paire de clés pour vous connecter en SSH à l'instance.  Utilisez le nom d'utilisateur « ubuntu » pour l'instance Linux EC2.  Pour les agents créés avant mai 2023, utilisez le nom d'utilisateur « ec2-user ».
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentation AWS : connectez-vous à votre instance Linux"^]

--
Azuré:: Lorsque vous créez la machine virtuelle de l’agent dans Azure, vous spécifiez un nom d’utilisateur et choisissez de vous authentifier avec un mot de passe ou une clé publique SSH.  Utilisez la méthode d’authentification que vous avez choisie pour vous connecter à la machine virtuelle.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure Docs : Connectez-vous à votre machine virtuelle via SSH"^]

--
Google Cloud:: Vous ne pouvez pas spécifier de méthode d'authentification lorsque vous créez un agent dans Google Cloud.  Cependant, vous pouvez vous connecter à l'instance de machine virtuelle Linux à l'aide de la console Google Cloud ou de Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs : Se connecter aux machines virtuelles Linux"^]
