= Déployer un agent de Console dans AWS depuis NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Déployez un agent Console dans AWS sans quitter la NetApp Console afin de pouvoir commencer à gérer vos ressources et services de données AWS.

Le déploiement d’un Console agent dans AWS lance une instance EC2 exécutant Linux et le logiciel Console agent dans le VPC de votre choix.

.Avant de commencer
* link:concept-agent-install-options.html#agent-console-deploy["Découvrez quand déployer depuis la console"].
* Revoirlink:reference-limitations.html["Limitations de l'agent de console"] .

== Étape 1 : Configurer le réseau pour déployer un agent Console dans AWS

Assurez-vous que l’emplacement réseau où vous prévoyez de déployer le Console agent répond aux exigences suivantes. Ces exigences permettent au Console agent de gérer les ressources et les processus de votre cloud hybride.

VPC et sous-réseau:: Lorsque vous créez l’agent de console, vous devez spécifier le VPC et le sous-réseau où il doit résider.


Connexions aux réseaux cibles:: L'agent de console nécessite une connexion réseau à l'emplacement où vous prévoyez de créer et de gérer des systèmes.  Par exemple, le réseau sur lequel vous prévoyez de créer des systèmes Cloud Volumes ONTAP ou un système de stockage dans votre environnement local.


Accès Internet sortant:: L’emplacement réseau où vous déployez l’agent de console doit disposer d’une connexion Internet sortante pour contacter des points de terminaison spécifiques.


Points de terminaison contactés depuis l'agent de la console:: L'agent de console nécessite un accès Internet sortant pour contacter les points de terminaison suivants afin de gérer les ressources et les processus au sein de votre environnement de cloud public pour les opérations quotidiennes.
+

Points de terminaison contactés depuis la console NetApp:: Lorsque vous utilisez l'application SaaS NetApp Console basée sur le Web, celle-ci contacte plusieurs points de terminaison pour effectuer des tâches de gestion des données. Serveur proxy:: NetApp prend en charge les configurations de proxy explicites et transparentes.  Si vous utilisez un proxy transparent, vous devez uniquement fournir le certificat du serveur proxy.  Si vous utilisez un proxy explicite, vous aurez également besoin de l'adresse IP et des informations d'identification.
+
--
* adresse IP
* Informations d'identification
* Certificat HTTPS


--


Ports:: Aucun trafic entrant n'est reçu par l'agent Console, sauf si vous l'initiez ou s'il est utilisé comme proxy pour envoyer des messages AutoSupport de Cloud Volumes ONTAP au support NetApp.
+
--
* HTTP (80) et HTTPS (443) donnent accès à l'interface utilisateur locale, que vous utiliserez dans de rares circonstances.
* SSH (22) n'est nécessaire que si vous devez vous connecter à l'hôte pour le dépannage.
* Les connexions entrantes via le port 3128 sont requises si vous déployez des systèmes Cloud Volumes ONTAP dans un sous-réseau où une connexion Internet sortante n'est pas disponible.
+
Si les systèmes Cloud Volumes ONTAP ne disposent pas d'une connexion Internet sortante pour envoyer des messages AutoSupport , la console configure automatiquement ces systèmes pour utiliser un serveur proxy inclus avec l'agent de la console.  La seule exigence est de s’assurer que le groupe de sécurité de l’agent de console autorise les connexions entrantes sur le port 3128.  Vous devrez ouvrir ce port après avoir déployé l’agent de console.



--


Activer NTP:: Si vous prévoyez d'utiliser NetApp Data Classification pour analyser vos sources de données d'entreprise, vous devez activer un service Network Time Protocol (NTP) à la fois sur l'agent de la Console et sur le système NetApp Data Classification afin que l'heure soit synchronisée entre les systèmes. https://docs.netapp.com/us-en/data-services-data-classification/concept-cloud-compliance.html["En savoir plus sur NetApp Data Classification"^]
+
--
Vous devrez implémenter cette exigence de mise en réseau après avoir créé l’agent de console.

[[step-2-set-up-aws-permissions-to-deploy-the-console-agent]]
[[aws-permissions-agent]]
== Étape 2 : Configurer les autorisations AWS pour déployer l’agent Console

N’accordez à la Console que les autorisations AWS dont elle a besoin pour déployer l’agent Console dans votre VPC, en fonction de la méthode d'authentification que vous choisissez.

Choisissez l'une de ces méthodes d'authentification et configurez uniquement ce qui est nécessaire :

[cols="1a,2a,2a"]
|===
| Méthode | Ce que cela fait | Ce que vous avez configuré 


 a| 
*Créez un rôle pour moi*
 a| 
La Console ouvre AWS CloudFormation Quick Create, qui crée le rôle de déploiement que la Console endosse.
 a| 
Autorisations pour l'identité AWS qui soumet la pile.



 a| 
*Assumer le rôle*
 a| 
La Console endosse un rôle IAM existant dans votre compte.
 a| 
Une politique et un rôle IAM.



 a| 
*Clés AWS*
 a| 
La Console utilise une clé d'accès AWS et une clé secrète AWS.
 a| 
Une stratégie et un utilisateur IAM.

|===
Avec *Créer un rôle pour moi* et *Assumer un rôle*, la Console assume un rôle IAM, appelé *rôle de déploiement*, pour déployer le *Console agent*. Après le déploiement, le *Console agent* utilise un rôle IAM distinct attaché à son instance EC2, appelé *rôle d'agent*. Par défaut, la Console crée le rôle d'agent pour vous. link:#aws-agent-role["Apprenez à utiliser votre propre rôle d'agent"].



[[set-up-permissions-for-create-role-for-me-cloudformation-quick-create]]
[[aws-permissions-quick-create]]
=== Configurer les autorisations pour Créer le rôle pour moi (CloudFormation Quick Create)

Utilisez une identité AWS capable de créer la pile CloudFormation et le rôle de déploiement, afin que la pile s'exécute sans erreurs d'autorisation.

L'identité qui soumet la pile Quick Create CloudFormation doit disposer de droits d'administrateur ou des droits minimaux suivants. Ces droits permettent à CloudFormation de créer le rôle de déploiement. Il ne s'agit pas des droits du rôle d'agent.

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationStack",
      "Effect": "Allow",
      "Action": [
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:GetTemplateSummary",
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:GetRole",
        "iam:PutRolePolicy",
        "iam:DeleteRolePolicy",
        "iam:GetRolePolicy",
        "iam:PassRole",
        "lambda:CreateFunction",
        "lambda:DeleteFunction",
        "lambda:GetFunction",
        "lambda:InvokeFunction"
      ],
      "Resource": "*"
    }
  ]
}
----


[[set-up-permissions-for-assume-role-or-aws-keys]]
[[aws-permissions-assume-role-keys]]
=== Configurez les autorisations pour Assume role ou les clés AWS

Si vous choisissez *Assume role* ou *AWS keys*, créez une stratégie avec uniquement les autorisations nécessaires pour déployer le Console agent, et associez-la au rôle ou à l'utilisateur que la Console utilise.

Si nécessaire, vous pouvez restreindre la politique IAM en utilisant l'IAM `Condition` élément. https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html["Documentation AWS : élément de condition"^]

.Étapes
. Accédez à la console AWS IAM.
. Sélectionnez *Politiques > Créer une politique*.
. Sélectionnez *JSON*.
. Copiez et collez la politique suivante :
+
Cette politique contient uniquement les autorisations nécessaires pour lancer le Console agent dans AWS depuis la Console link:reference-permissions-aws.html["Afficher les autorisations du rôle d'agent"].

+
[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",
        "iam:RemoveRoleFromInstanceProfile",
        "iam:DeleteInstanceProfile",
        "iam:PassRole",
        "iam:ListRoles",
        "ec2:DescribeInstanceStatus",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:CreateSecurityGroup",
        "ec2:DeleteSecurityGroup",
        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",
        "ec2:DescribeNetworkInterfaces",
        "ec2:DeleteNetworkInterface",
        "ec2:ModifyNetworkInterfaceAttribute",
        "ec2:DescribeSubnets",
        "ec2:DescribeVpcs",
        "ec2:DescribeDhcpOptions",
        "ec2:DescribeKeyPairs",
        "ec2:DescribeRegions",
        "ec2:DescribeInstances",
        "ec2:CreateTags",
        "ec2:DescribeImages",
        "ec2:DescribeAvailabilityZones",
        "ec2:DescribeLaunchTemplates",
        "ec2:CreateLaunchTemplate",
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:ValidateTemplate",
        "ec2:AssociateIamInstanceProfile",
        "ec2:DescribeIamInstanceProfileAssociations",
        "ec2:DisassociateIamInstanceProfile",
        "iam:GetRole",
        "iam:TagRole",
        "kms:ListAliases",
        "cloudformation:ListStacks"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:TerminateInstances"
      ],
      "Condition": {
        "StringLike": {
          "ec2:ResourceTag/OCCMInstance": "*"
        }
      },
      "Resource": [
        "arn:aws:ec2:*:*:instance/*"
      ]
    }
  ]
}
----
. Sélectionnez *Suivant* et ajoutez des balises, si nécessaire.
. Sélectionnez *Suivant* et entrez un nom et une description.
. Sélectionnez *Créer une politique*.
. Attachez la politique à un rôle IAM que la console peut assumer ou à un utilisateur IAM afin de pouvoir fournir à la console des clés d'accès :
+
** *Assumer un rôle* : Configurez un rôle IAM que la Console peut assumer :
+
... Accédez à la console AWS IAM dans le compte cible.
... Sous Gestion des accès, sélectionnez *Rôles > Créer un rôle* et suivez les étapes pour créer le rôle.
... Sous *Type d’entité approuvée*, sélectionnez *Compte AWS*.
... Sélectionnez *Un autre compte AWS* et saisissez l'ID du compte SaaS de la console : 952013314444
... Sélectionnez la politique que vous avez créée dans la section précédente.
... Après avoir créé le rôle, copiez l’ARN du rôle afin de pouvoir le coller dans la console lorsque vous créez l’agent de console.


** *Clés AWS* : Configurez les autorisations d’un utilisateur IAM afin de pouvoir fournir à la Console des clés d’accès :
+
... Depuis la console AWS IAM, sélectionnez *Utilisateurs*, puis sélectionnez le nom d’utilisateur.
... Sélectionnez *Ajouter des autorisations > Joindre directement les politiques existantes*.
... Sélectionnez la politique que vous avez créée.
... Sélectionnez *Suivant* puis sélectionnez *Ajouter des autorisations*.
... Assurez-vous que vous disposez de la clé d’accès et de la clé secrète de l’utilisateur IAM.






.Résultat
Vous disposez désormais d'un rôle de déploiement ou d'un utilisateur IAM possédant les autorisations requises. Lorsque vous déployez Console agent, vous fournissez l'ARN du rôle ou les clés d'accès.



[[step-3-set-up-your-own-iam-role-for-the-console-agent-optional]]
[[aws-agent-role]]
== Étape 3 : Configurez votre propre rôle IAM pour le Console agent (facultatif)

Créez votre propre rôle d’agent si vous souhaitez le sélectionner à la place du rôle que la Console crée par défaut. Créez le rôle avant de déployer le Console agent.

.Étapes
. Connectez-vous à la console AWS et accédez au service IAM.
. Créer une politique:
+
.. Sélectionnez *Politiques > Créer une politique*.
.. Sélectionnez *JSON* et copiez et collez le contenu dulink:reference-permissions-aws.html["Politique IAM pour l'agent de console"] .
.. Terminez les étapes restantes pour créer la politique.
+
Pour les régions standard, les autorisations sont réparties sur deux politiques.  Deux politiques sont requises en raison d'une limite de taille maximale de caractères pour les politiques gérées dans AWS. link:reference-permissions-aws.html["En savoir plus sur les stratégies IAM pour l'agent de console"] .



. Créer un rôle IAM :
+
.. Sélectionnez *Rôles > Créer un rôle*.
.. Sélectionnez *Service AWS > EC2*.
.. Ajoutez des autorisations en joignant la politique que vous venez de créer.
.. Terminez les étapes restantes pour créer le rôle.




.Résultat
Vous disposez désormais d'un rôle d'agent que vous pouvez sélectionner dans *Agent deployment details* lors du déploiement du Console agent.



[[step-4-deploy-the-console-agent]]
== Étape 4 : Déployer l’agent Console

Fournissez vos informations d'authentification, de déploiement, de réseau et de groupe de sécurité afin que la Console lance le Console agent dans votre VPC.

.À propos de cette tâche
* La création de l’agent de console à partir de la console déploie une instance EC2 dans AWS à l’aide d’une configuration par défaut.  Ne passez pas à une instance EC2 plus petite avec moins de processeurs ou moins de RAM après avoir créé l'agent de console. link:reference-agent-default-config.html["En savoir plus sur la configuration par défaut de l'agent de console"] .
* Par défaut, la Console crée le rôle d'agent et son profil. Si vous fournissez votre propre rôle d'agent, veillez à le mettre à jour lorsque de nouvelles autorisations seront ajoutées dans les versions ultérieures. link:reference-permissions-aws.html["En savoir plus sur la politique IAM pour l'agent de console"].


.Avant de commencer
Vous devriez avoir les éléments suivants :

* Une méthode d'authentification AWS : *Create role for me*, *Assume role* ou *AWS keys*.
* Un VPC et un sous-réseau qui répondent aux exigences de mise en réseau.
* Une paire de clés pour l'instance EC2.
* Détails sur un serveur proxy, si un proxy est requis pour l'accès Internet à partir de l'agent de la console.
* Terminé link:#networking-aws-agent["Étape 1"].
* Terminé link:#aws-permissions-agent["Étape 2"].


.Étapes
. Sélectionnez *Administration > Agents*.
. Sur la page *Aperçu*, sélectionnez *Déployer l’agent > AWS*.
. Dans la section *Identifiants AWS pour le déploiement de l'agent*, choisissez l'une des méthodes d'authentification suivantes :
+
** *Créez un rôle pour moi*:
+
... Sélectionnez votre région AWS et saisissez l'ID de votre compte AWS. Vous pouvez également saisir un ID externe.
... Sélectionnez *Open CloudFormation Quick Create*.
... Dans AWS, acceptez les conditions et sélectionnez *Créer une pile*.
... Une fois qu'AWS a terminé de créer le rôle, retournez à la Console et confirmez le rôle.


** *Assume role* : Saisissez l’ARN du rôle IAM et sélectionnez *Validate credentials*.
** *Clés AWS* : Saisissez la clé d’accès et la clé secrète, puis sélectionnez *Valider les informations d’identification*.


. Dans la section *Détails du déploiement de l’agent*, fournissez des informations sur l’agent Console.
+
** Entrez un nom.
** Ajouter des balises personnalisées (métadonnées).
** Choisissez si vous souhaitez que la Console crée le rôle d'agent, ou sélectionnez un rôle d'agent que vous link:#aws-agent-role["configurez vous-même"] avez choisi.
** Choisissez si vous souhaitez crypter les disques EBS de l'agent de console.  Vous avez la possibilité d’utiliser la clé de chiffrement par défaut ou d’utiliser une clé personnalisée.


. Dans la section *Configuration réseau*, spécifiez un VPC, un sous-réseau et une paire de clés pour le Console agent, choisissez d’activer ou non une adresse IP publique et, si vous le souhaitez, spécifiez une configuration de proxy.
+
Assurez-vous que vous disposez de la paire de clés correcte pour accéder à la machine virtuelle de l’agent de console.  Sans une paire de clés, vous ne pouvez pas y accéder.

. Dans la section *Groupe de sécurité*, choisissez si vous souhaitez créer un nouveau groupe de sécurité ou sélectionner un groupe de sécurité existant qui autorise les règles entrantes et sortantes requises.
+
link:reference-ports-aws.html["Afficher les règles du groupe de sécurité pour AWS"] .



. Vérifiez vos sélections pour vous assurer que votre configuration est correcte.
+
.. La case à cocher *Valider la configuration de l’agent* est activée par défaut afin que la NetApp Console valide les exigences de connectivité réseau lors du déploiement. Si la NetApp Console ne parvient pas à déployer l’agent, un rapport est fourni pour vous aider à résoudre le problème. Si le déploiement réussit, aucun rapport n’est fourni.


+
[NOTE]
====
** Si vous utilisez encore l'link:reference-networking-saas-console-previous.html["points finaux précédents"] utilisé pour les mises à niveau de l'agent, la validation échoue avec une erreur. Pour éviter cela, décochez la case à cocher pour ignorer la vérification de validation.
** Lors de l'installation, NetApp vérifie que l'hôte de l'agent dispose d'au moins 80 % de l'espace disque total disponible, ce qui inclut 48 Go dans  `/opt` et 32 Go dans  `/var` (80 Go au total). Après l'installation, il est nécessaire qu'au moins 20 % de l'espace disque total reste disponible, ce qui inclut 12 Go dans  `/opt` et 8 Go dans  `/var` (20 Go au total).


====
. Sélectionnez *Ajouter*.
+
La Console déploie le Console agent en environ 10 minutes. Veuillez rester sur la page jusqu'à la fin du processus.



.Résultat
Une fois le processus terminé, l’agent de la console peut être utilisé à partir de la console.

Si vous avez des compartiments Amazon S3 dans le même compte AWS où vous avez créé l'agent de console, vous verrez un environnement de travail Amazon S3 apparaître automatiquement sur la page *Systèmes*. https://docs.netapp.com/us-en/storage-management-s3-storage/index.html["Apprenez à gérer les buckets S3 depuis la NetApp Console"^]

== Résolution des problèmes liés à l’échec du déploiement de l’agent Console

Utilisez le rapport de déploiement pour identifier ce qui a bloqué le déploiement de l'agent Console, puis réessayez.

La Console fournit un rapport uniquement si la case à cocher *Validate agent configuration* a été sélectionnée. Si le déploiement réussit, aucun rapport n'est généré.

.Étapes
. Dans la boîte de dialogue *Échec du déploiement de l'agent*, sélectionnez *Télécharger le rapport*.
+
La Console télécharge un fichier PDF contenant le rapport de validation.

. Examinez le rapport et corrigez les problèmes qu'il recense.
. Dans la boîte de dialogue, sélectionnez *Recommencer*, puis effectuez de nouveau le déploiement.
+
Vous devez recommencer tout le processus pour réessayer.



link:task-troubleshoot-agent.html#troubleshoot-installation["Découvrez comment résoudre les problèmes d’installation."]
