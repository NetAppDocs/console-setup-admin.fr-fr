= En savoir plus sur les agents de la NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Un agent de Console est un composant logiciel léger que vous installez sur votre réseau pour connecter votre infrastructure de stockage à la NetApp Console. Il permet une orchestration avancée du stockage, des services de données et une intégration au cloud.



== Que fait un agent de Console

Un agent Console assure la connectivité entre vos systèmes de stockage et NetApp Console. Il connecte votre infrastructure aux API NetApp et à la Console de manière sécurisée, vous permettant ainsi de :

* Découvrez et surveillez les systèmes de stockage sur AWS, Azure, Google Cloud et les environnements sur site depuis la NetApp Console.
* Orchestrez les tâches de provisionnement et de configuration du stockage sur les systèmes de stockage depuis la NetApp Console.
* Utilisez des workflows intelligents pour la protection et la gestion des données.
* Suivez en toute sécurité l'utilisation des services cloud et connectez les déploiements à l'abonnement approprié pour une facturation et une gestion des coûts précises.




=== architecture de l'agent de console

Les agents fonctionnent avec des processus légers qui :

* Extraire ou envoyer des données depuis et vers l'application SaaS Console (modes standard et restreint)
* Initiez toutes les communications : la Console n’initie jamais d’appels sortants vers les agents
* Connectez-vous à vos systèmes de stockage à l'aide de protocoles de gestion standard
* Utilisez TLS 1.3 pour une communication sécurisée avec les fournisseurs de cloud et les API de la console NetApp




=== Disponibilité de l'agent de console et exigences opérationnelles

Les agents de la console sont essentiels pour NetApp Console. Les agents doivent rester opérationnels et joignables pour garantir la continuité des services de gestion et de données. Il vous incombe de veiller à ce que :

* Les agents restent opérationnels
* Les agents disposent d'une connectivité réseau avec les points de terminaison requis
* Les pannes d'infrastructure sont résolues rapidement
* Les machines virtuelles des agents sont maintenues et mises à niveau conformément aux recommandations de NetApp




== Lorsque vous avez besoin d'un agent Console

Vous devez déployer au moins un agent Console lorsque vous souhaitez :

* Utilisez les modes de déploiement restreints ou privés (Console installée dans votre propre environnement). Des agents supplémentaires peuvent être nécessaires pour activer certains services.
* Accédez à des services de données avancés (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification et plus encore).
* Gérez les systèmes Cloud Volumes ONTAP.
* Effectuer des tâches de gestion avancées sur les clusters ONTAP sur site.
* Suivez les licences, surveillez la santé du stockage et planifiez les mises à niveau du cycle de vie.


Sans agent, vous pouvez effectuer une découverte de stockage de base et accéder à un ensemble limité de fonctionnalités de surveillance et de gestion du stockage. Cependant, la plupart des cas d'utilisation en entreprise nécessitent un ou plusieurs agents opérationnels.

== Options de déploiement pour les agents Console

Vous pouvez déployer des agents Console dans :

* Amazon Web Services
* Microsoft Azure
* Google Cloud
+
Pour gérer les ressources Google Cloud, déployez votre agent dans Google Cloud. Un agent installé sur site ne peut pas gérer les ressources Google Cloud.

* Dans vos locaux (modes standard ou privés uniquement)


Le mode de déploiement de votre Console, l'environnement de stockage et les besoins en matière de souveraineté des données déterminent où vous déployez les agents. Déployez plusieurs agents dans différents environnements pour une séparation organisationnelle ou selon les besoins de l'entreprise.

Vous pouvez déployer des agents directement depuis la console, depuis votre place de marché cloud, ou manuellement dans vCenter ou sur site. link:concept-agent-install-options.html["Comparez les méthodes de déploiement pour choisir celle qui convient le mieux à votre environnement"].



=== Agents pour l'application SaaS NetApp Console (mode standard)

Déployez des agents dans votre cloud ou sur site pour assurer la connectivité avec l'application SaaS Console hébergée dans le cloud. Les agents activent des fonctionnalités avancées tandis que l'interface utilisateur de la Console reste accessible de partout.

Vous pouvez installer les agents directement depuis la Console lorsque vous utilisez l'application SaaS (mode standard). Vous pouvez installer dans AWS, Azure ou Google Cloud, ou manuellement sur votre propre hôte Linux ou dans votre environnement VCenter.



=== Agents pour NetApp Console en mode restreint

En mode restreint, les utilisateurs accèdent à la NetApp Console directement depuis un agent installé, et non depuis l'application SaaS hébergée dans le cloud. Vous devez installer au moins un agent pour servir de point d'accès à la Console. Des agents supplémentaires sont nécessaires pour activer les services de données et gérer les systèmes de stockage.

Installez les agents depuis la place de marché de votre fournisseur de cloud ou en installant manuellement le logiciel sur votre propre hôte Linux dans le cloud, sur vos locaux ou dans votre environnement VCenter.



=== Agents pour NetApp Console en mode privé (sur site ou dans le cloud sans connectivité sortante)

En mode privé, les utilisateurs accèdent à la NetApp Console directement depuis un agent installé. Vous devez installer au moins un agent pour servir de point d'accès à la Console. Des agents supplémentaires sont nécessaires pour activer les services de données et gérer les systèmes de stockage.

Installez les agents dans votre centre de données ou votre environnement isolé. Les agents n'ont aucune connexion aux points de terminaison API NetApp, et toutes les opérations restent locales, avec une souveraineté des données et un contrôle complets.



=== Utilisez plusieurs agents lorsque nécessaire

Chaque agent fonctionne indépendamment et peut gérer plusieurs systèmes de stockage et services de données. Déployez plusieurs agents lorsque vous avez besoin :

* Isolation par type de stockage ou fonction organisationnelle
* exigences de segmentation géographique ou de réseau


Par exemple:

* Dans un environnement multicloud, vous pouvez déployer un agent sur AWS et un autre sur Azure. Chaque agent gère les systèmes Cloud Volumes ONTAP dans son environnement respectif.
* Un fournisseur de services peut utiliser une organisation Console pour fournir des services aux clients et une autre organisation pour la reprise après sinistre d'une unité commerciale. Chaque organisation a besoin de son propre agent.




== Mises à niveau de l'agent de console

Les agents dans le cloud se mettent à jour automatiquement dès qu'ils disposent d'un accès Internet sortant. Pour les agents sans accès Internet (mode privé), consultez link:task-upgrade-agent.html["Gérer les mises à niveau de l'agent de la console"] les instructions de mise à jour manuelle.
