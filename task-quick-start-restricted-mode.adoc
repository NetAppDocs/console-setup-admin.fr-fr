= Démarrage rapide pour NetApp Console en mode restreint
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Commencez à utiliser la NetApp Console en mode restreint en préparant votre environnement et en déployant l’agent de la console.

Le mode restreint est généralement utilisé par les gouvernements étatiques et locaux et les entreprises réglementées, y compris les déploiements dans les régions AWS GovCloud et Azure Government.  Avant de commencer, assurez-vous d'avoir une bonne compréhension delink:concept-agents.html["Agents de console"] etlink:concept-modes.html["modes de déploiement"] .

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["Un"] link:task-prepare-restricted-mode.html["Préparez-vous au déploiement"]
[role="quick-margin-list"]
. Vérifiez la configuration requise pour l'hôte. En cas d'installation manuelle, préparez un hôte Linux dédié répondant aux exigences en matière de processeur, de mémoire vive, d'espace disque et d'outil d'orchestration de conteneurs. link:task-prepare-restricted-mode.html#step-3-review-host-requirements["Examiner les exigences de l'hôte"].
. Configurez un réseau qui fournit un accès aux réseaux cibles, un accès Internet sortant pour les installations manuelles et un accès Internet sortant pour l'accès quotidien.
. Préparez les autorisations cloud requises pour votre fournisseur et votre méthode de déploiement.


.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["Deux"] Déployer l’agent Console
[role="quick-margin-list"]
. Choisissez les instructions de déploiement pour votre environnement cloud :
+
** AWS : link:task-install-restricted-mode-aws.html["Déployer dans AWS"]
** Azure : link:task-install-restricted-mode-azure.html["Déployer dans Azure"]
** Installation manuelle : link:task-install-restricted-mode-manual.html["Déployer manuellement dans AWS, Azure ou Google Cloud"]


. Configurez la NetApp Console en ouvrant un navigateur Web et en saisissant l’adresse IP de l’hôte Linux.
. Suivez les instructions spécifiques à votre fournisseur pour associer les autorisations requises à l’agent Console. Pour les déploiements AWS Marketplace, sélectionnez le rôle IAM lors du lancement de l’instance EC2.


.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["Trois"] link:task-subscribe-restricted-mode.html["Abonnez-vous aux NetApp Intelligent Services (facultatif)"]
[role="quick-margin-para"]
En option : abonnez-vous à NetApp Intelligent Services depuis la place de marché de votre fournisseur de cloud pour payer les services de données à l’heure (PAYGO) ou via un contrat annuel. NetApp Intelligent Services inclut NetApp Backup and Recovery, Cloud Volumes ONTAP, NetApp Ransomware Resilience et NetApp Disaster Recovery. NetApp Data Classification est inclus dans votre abonnement sans coût supplémentaire.

[NOTE]
====
NetApp Cloud Tiering n'est plus disponible à l'achat ni au renouvellement de licence depuis le 26 avril 2026.

Les clients existants peuvent continuer à utiliser et à bénéficier du support pour NetApp Cloud Tiering jusqu'à l'expiration de leur abonnement ou de leur contrat de licence. Après l'expiration de l'abonnement, les clients n'auront plus accès aux fonctionnalités ou au support de NetApp Cloud Tiering.

NetApp recommande aux clients de collaborer avec leur représentant NetApp pour convertir leurs licences de hiérarchisation existantes en licences FabricPool ONTAP, qui offrent la fonctionnalité de hiérarchisation des données dans ONTAP. Pour plus d'informations sur la configuration de la hiérarchisation des données dans ONTAP à l'aide de FabricPool, voir link:https://docs.netapp.com/us-en/ontap/fabricpool/install-license-aws-azure-ibm-task.html["Installez une licence FabricPool sur un cluster ONTAP"^].
